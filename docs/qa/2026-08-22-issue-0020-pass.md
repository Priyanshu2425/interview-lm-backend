## What this pass changed about how the criteria are checked

Three of the four outstanding items were treated as "needs a person" because
they *look* like judgements. Two of them are not, and the difference is worth
naming, because it is the difference between a check that runs on every commit
and a check that ran once.

**A screen reader pass** is a judgement about listening. *What a screen reader
would announce* is not: it is the accessibility tree, and the tree can be read.
`npm run a11y` reads it over CDP — the same data the devtools pane shows — and
asserts the criterion as written: is there a name, and does it carry the meaning
rather than the decoration.

**A side-by-side fidelity comparison** has two halves. Whether the built screen
*looks* like the drawn one is a judgement. Whether it *says the same things* —
the same sections, the same controls, the same words for them — is an inventory,
and an inventory diffs. `npm run fidelity` renders each prototype screen and its
built counterpart at 390, 768 and 1440 and prints what the prototype says that
the build does not.

**The copy sweep** and the **keyboard Session** are in `test:e2e`, so a
regression fails a run rather than waiting for the next read.

## Two defects, found and fixed

**A band was carried by colour alone.** `Reading` renders the figure for a
tested Topic and the word only for an untested one, so `0.60` said nothing about
whether the system calls that weak or solid — the band was a tint, and a tint is
the one thing a greyscale screen and a screen reader both lose. The server
already decides the band and hands over its label, so the fix is to say it:
a screen-reader-only span carrying the server's own word. No second
implementation of the Evidence Floor, and the visual design is unchanged.

**The examination screen had no heading.** The product's central screen. The
topbar rendered its title as `<strong>`, which reads as emphasis rather than as
structure, so a reader navigating by headings had nothing to land on — on every
screen, at every width. `PageHeader` now marks the title as a level-1 heading,
and the mobile restatement of the Topic title was demoted from `<h1>` to a
paragraph so the same words are not announced as two headings.

**And one the first fix caused.** The screen-reader-only span is absolutely
positioned; `.table-scroll` was not a containing block, so deep inside a 760px
Evidence table the span escaped its scroller, landed at x=543 and took the whole
page sideways at 390px — 153px of horizontal scroll on the Session record. The
fidelity pass caught it on the run after the one that introduced it, which is
the argument for having written it. `.table-scroll` is `position: relative` now,
which is what makes its `overflow-x` actually clip.

## Every failure message, reviewed

The rule: name the problem and the recovery, and never send a Candidate to fix
something that is not broken.

**The structural answer first.** Failure copy is rendered from the API's own
`code` and `message`; the client composes none. That is what makes the runbook's
worst case — a connection problem answered with an offer to top up — not merely
unobserved but unreachable: a Credit message exists only in a 402 body, and a
dropped connection does not produce one.

| Message | Problem | Recovery |
|---|---|---|
| *Ingest did not start* + `it needs N Credits and the balance is M, short by K` | named, with the figure | named: the shortfall is the amount |
| *This Session is waiting, not lost* + the park's own message | named, with the provider | a Resume button beside it |
| *Nothing to resume* | named | there is nothing to do, and it says so |
| *It was not deleted / removed / retried / revoked* + API message | named | the API's message carries it; the action stays available |
| *That key was refused* + API message | named | the field stays filled and re-submittable |
| *The Session did not start* + API message | named | scope is still chosen; the control stays live |
| *This Library was imported once and is shared…* (`corpus_is_shared`) | named, with the reason | none, and correctly: the answer is that this is not yours to delete |
| *…is ready: it has already been ingested* (`ingest_not_claimable`) | named | none needed; the work is done |
| *N figures and no text. Pictures alone are not examinable here…* | named | *"The document is kept, so it can be re-read if that ever changes."* |
| *That Session / record / ledger could not be read* + API message | named | the route is re-enterable; nothing was written |

None of them blames the Candidate, and none offers a purchase for a problem that
is not about money.

## What is left for a person

Two things, and they are smaller than they were.

**Listening to a real screen reader.** The tree says the names exist and carry
meaning. Whether VoiceOver's rendering of *"Looks solid. Mastery 0.82, drawn as
a Beta density."* is pleasant to hear in a sequence of forty rows is a question
about listening, and nothing here can answer it.

**Looking at the two screens side by side.** Every word the prototype says is
accounted for above, at three widths, and nothing overflows or fails contrast.
Whether the built screen *is* the drawn screen — weight, rhythm, the feel of the
ink surface — is a judgement, and `design-system/` is a static mock with
hard-coded content, so there is no automatic diff that would not be comparing a
photograph to a building.
